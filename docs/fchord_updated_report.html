JSON Schema — 介面契約
Flutter 傳給 FastAPI（Input）
{
  "nodes": float[21][3] // 21 個關節 [x,y,z] 0–1
}
FastAPI 回傳給 Flutter（Output）
{
  "label": string // GNN 分類結果
  "confidence": float // 信心度 0–1
  "node_status": int[21] // 0=ok 1=warn 2=err
  "ghost_nodes": float[21][2] // 只傳一次，你快取
  "error_duration_ms": int // 連續錯誤毫秒數
  "suggestion": string | null // VLM 中文建議
  "frame_ms": int // 推理耗時 debug 用
}
欄位說明更新頻率產生者
nodeshand_detection 拿到的 21 個關節座標，normalized 0–1。你的 CustomPainter 乘以螢幕寬高換成像素後畫在相機畫面上每幀更新Flutter（你）
node_status每個關節狀態，0=正確（綠）、1=警告（橘）、2=錯誤（紅）。你根據這個決定 CustomPainter 節點顏色每幀更新GNN 模型（朋友）
labelGNN 判斷目前屬於哪種錯誤類型。你的 Flutter UI 根據這個值顯示對應中文提示，需要朋友提供完整清單每幀更新GNN 模型（朋友）
confidenceGNN 對分類的信心度。可設門檻（如 <0.6 不顯示錯誤提示），或只在 debug 模式顯示每幀更新GNN 模型（朋友）
ghost_nodesF chord 正確骨架的目標位置（標準答案），固定不動。只在第一次回傳，Flutter 快取後用 CustomPainter 畫成黃色虛線疊在真實骨架上只傳一次，Flutter 快取GNN 模型（朋友）
error_duration_ms連續錯誤持續幾毫秒。你在 FastAPI 計時，Flutter 可顯示計時器，超過 3000ms 代表 VLM 即將觸發每幀更新FastAPI（你）
suggestionVLM 看完截圖後的中文建議，平常是 null，錯誤超過 3 秒才觸發非同步回傳。你的 FastAPI 負責呼叫 VLM 並限流，Flutter 顯示在 Feedback Card觸發才更新（非同步）VLM API（你串接）
frame_ms這幀推理耗時毫秒，你在 FastAPI 計時後回傳，Flutter debug 模式顯示，確認是否達到 <30ms 目標每幀更新FastAPI（你）
Label 清單（待朋友 W2 前最終確認）
Label 值意思Flutter UI 顯示的中文提示
correct姿勢正確✅ 姿勢正確！繼續保持
err_index_low食指位置太低食指需要往上移到第一格正中間
err_index_high食指位置太高食指位置太高，往下移一點
err_middle_mute中指悶到其他弦中指碰到旁邊的弦，稍微抬高指尖
err_ring_mute無名指悶到其他弦無名指碰到旁邊的弦，調整角度
err_thumb_wrong大拇指位置不對大拇指移到琴頸正後方
待確認 清單為預估值，最終由朋友訓練資料的分類類別決定。W2 前確認完整清單後，你才能在 Flutter 把所有中文對應文字寫好。

你需要在 Flutter 對應每個 label 值顯示中文提示文字，不知道完整清單就沒辦法寫。上面的清單是預估，需要朋友從訓練資料的分類類別確認最終版本。
W2 必須確認
Q2
ghost_nodes 是只在第一次回傳，還是 ONNX 沒有這個輸出？
ghost_nodes 邏輯上是固定的標準答案，只傳一次就好。但需要確認朋友的 ONNX 輸出是否包含這個欄位，還是你要在 FastAPI 自己 hardcode。
W2 必須確認
Q3
ONNX 的輸入輸出 tensor 格式？
你的 FastAPI 要載入朋友的 fchord.onnx，需要知道輸入 tensor 的 shape 和 dtype，以及輸出欄位的格式，才能正確串接。
