W1 – W2 骨架 Prototype — 桌面版跑通 Dev 先行
Dev Team
  • 環境建置：Python 3.11 + MediaPipe + OpenCV + PyTorch Geometric
  • Keypoint 擷取：webcam 即時輸出 21 個 [x,y,z]，視覺化確認
  • Skeleton overlay：依 FINGER_CONNECTIONS 畫連線，綠/紅節點
  • Ghost F chord：hardcode 目標骨架，黃色虛線疊加
  • 角度計算：angle_between() 每關節輸出
  • QC script：fchord_qc.py 以假資料測試通過
Frontend Team
  • Flutter 環境建置：iOS / Android 模擬器跑通
  • 設計系統：色票、字體、間距規範，Figma file 開工
  • Camera preview：基礎全螢幕相機 + 靜態 UI frame
  • Wireframe：主畫面 / 進度畫面低保真稿
  • CustomPainter 研究：能在 camera feed 上畫線的 prototype
Sync W2 Dev 輸出 JSON schema 草稿 · Frontend 確認 CustomPainter 能接收 node 座標並畫線 · 決定 D-01：On-device vs 雲端
W3 – W4 資料蒐集 + GNN 訓練 Dev 核心週
Dev Team
  • Labeling script：空白鍵拍照儲存 JSON，6 個 label 類別
  • 資料蒐集：~900 筆（含 3–5 位不同錄製者）
  • QC 執行：fchord_qc.py 全跑，刪除 FAIL 樣本
  • Graph 建構：PyG Data(x, edge_index, y) 格式
  • GraphSAGE 訓練：3 層 SAGEConv + global mean pooling
  • 評估：confusion matrix，目標 >85% val acc
  • ONNX export：輸出 fchord.onnx
Frontend Team
  • 主畫面 Hi-Fi：相機 + skeleton overlay + 手指狀態列
  • Overlay 動畫：節點顏色即時切換（綠/紅）動畫
  • Ghost overlay UI：黃色虛線骨架層，與真實骨架同框
  • Feedback card：底部浮現中文建議卡片 + 動畫
  • Mock data 串接：用假 JSON 把整個 UI 跑通，不等 model
Sync W4 Dev 交付 fchord.onnx / .tflite 給 Frontend · 雙方對齊 frame JSON schema v1 所有欄位 · Frontend 確認 mock UI 通過設計審查
W5 – W6 VLM 整合 + 真實 Model 串接 雙隊整合週
Dev Team
  • TFLite 轉換：ONNX → TFLite，目標 <30ms/frame
  • 觸發邏輯：錯誤計時器，超 3s 觸發 VLM call
  • VLM prompt 設計：截圖 + skeleton JSON → 中文建議 template
  • 限流機制：每分鐘最多 2 次，費用監控
  • FastAPI server（若採雲端方案）：/infer endpoint
  • 壓力測試：連跑 10 分鐘確認記憶體不 leak
Frontend Team
  • tflite_flutter 整合：真實 model 載入，替換 mock data
  • Frame pipeline：每幀 → model → overlay，<30ms 目標
  • VLM suggestion 顯示：非同步載入 + loading 動畫
  • Progress screen：練習時長、成功率統計
  • 本地儲存：SQLite 記錄每次 session
Sync W6 End-to-end demo：真實手機 + 真實手 + 真實 model 完整跑一次 · 確認 frame rate >20fps · VLM 建議 人工評分（5 人 × 10 筆）

D-01
On-device TFLite vs 雲端 FastAPI？
TFLite：無延遲、隱私好、model <20MB · FastAPI：方便迭代、無大小限制，需網路。建議先 FastAPI 驗證，V1.1 再轉 TFLite。
W2 決定
D-02
Flutter vs React Native？
Flutter：CustomPainter 對 overlay 支援好，tflite_flutter 成熟 · RN：若 FE Team 熟 JS 可選，但 canvas overlay 較複雜。
FE W1 決定
D-03
VLM 用哪個 API？
GPT-4o Vision 或 Claude 3.5 Sonnet 皆可。各測 10 筆，人工評中文建議品質後決定。預算 $50 beta 期間。
Dev W5 決定
D-04
Overlay 座標換算誰負責？
建議 Dev 輸出 normalized [0,1]，Frontend 根據螢幕解析度乘以 width/height。Frontend 最懂自己的 canvas 尺寸，不應由 Dev 推算。
W2 對齊
D-05
Beta 用戶招募來源？
PTT 吉他版、Dcard 音樂版、Facebook 吉他社團、學校吉他社。目標 10–15 人，承諾 1 週試用 + 15 分鐘訪談。
